# VersionDrift — план проекта (обзор на русском)

Подробные спецификации в `docs/` на английском: проект открытый и международный, так же удобнее контрибьюторам
и Claude Code. Этот файл — сжатая версия для чтения и принятия решений.

## Что делаем

Доска продуктов, которые ты эксплуатируешь. По каждому продукту видно:
- твою версию и последнюю версию;
- цвет статуса: красный (CVE затрагивает твою версию, CVSS ≥ 7 или есть в CISA KEV), тёмный (ветка в EOL),
  жёлтый (есть обновления), зелёный (актуально);
- сводный changelog от твоей версии до последней, где подсвечены security, breaking и deprecated;
- ленту «что вышло за неделю».

Продукты описываются YAML-модулями в открытом репозитории, новые модули сообщество присылает через PR.

## Главный принцип

Данные о продуктах публичные и собираются один раз централизованно. Твой инвентарь приватный:
- анонимно — только в браузере;
- с аккаунтом — только пары «продукт + версия»;
- в self-hosted — не покидает твой сервер.

## Режимы (один код)

1. **Публичный сайт без логина.** Всё видно сразу, версии хранятся в браузере, доской можно поделиться ссылкой.
2. **Публичный сайт с логином.** Синхронизация между устройствами, уведомления на почту и в Telegram, дайджест по воскресеньям.
3. **Self-hosted (Docker).** Автоопределение версий внутри контура: HTTP, SSH, Docker, SNMP, SQL, а также Zabbix,
   Proxmox и Ansible. Несколько инстансов одного продукта, приватные модули, уведомления.
4. **Команды** (позже): общие доски, SSO. Потенциально платный уровень.

## Стек

- TypeScript, монорепо на pnpm.
- Collector в GitHub Actions раз в сутки, feed в виде статичного JSON на Cloudflare R2 с подписью minisign.
- Сайт на SvelteKit: на Cloudflare для публичной версии, в Node и Docker для self-hosted.
- Drizzle ORM: D1 для аккаунтов, SQLite для self-hosted.

Всё бесплатно на старте.

## Название

Предложение: **VersionDrift**. «Version drift» — устоявшийся термин ровно для этой проблемы: насколько то, что у тебя
стоит, отстало от апстрима. Домены `versiondrift.dev` и `versiondrift.io` на 25.09.2026 не зарегистрированы.
Запасные варианты: Verscope, Patchsight, PatchLag (все `.dev` свободны). Имя «Stack Radar» из прототипа занято (stackradar.dev).

## Решения, которые нужно принять тебе

1. Название и регистрация доменов, GitHub-организации и ников в соцсетях.
2. Лицензия: AGPL-3.0 (защищает хостинг-версию от закрытых клонов) или MIT/Apache (максимальное распространение).
   Рекомендация: AGPL для кода, CC BY 4.0 для данных.
3. Провайдер LLM для классификации (S3), можно отложить.

## Как работать с Claude Code

1. Создай репозиторий, положи туда этот пакет, сделай `git init` и первый коммит.
2. Запусти `claude` в корне. `CLAUDE.md` загрузится автоматически: там принципы, стек, структура и ссылки на спецификации.
3. Давай задачи по номерам: «Сделай S0-T1 из docs/09-roadmap.md». Команда `/sprint-task S0-T1` делает то же самое.
4. Добавить модуль: `/new-module zabbix`.
5. После каждого спринта обновляй строку `Current sprint:` в `docs/09-roadmap.md`.
